# Установка и проверка агентов

GigaLoom работает с тремя источниками агентов:

| Источник | Что делает GigaLoom | Где искать |
|---|---|---|
| Встроенный профиль | Запускает уже установленный Codex, Claude, Gemini или Pi | `giga agent list` |
| ACP Registry | Загружает выбранный артефакт в собственный управляемый каталог | `giga agent search` |
| Локальный манифест | Регистрирует описание программы, которой управляете вы | `giga agent add --manifest` |

Установка из ACP Registry не меняет глобальный `npm`, Python или `PATH`.
Артефакты и результаты проверок хранятся внутри `GIGALOOM_DATA_DIR` (по
умолчанию `~/.gigaloom`). Домашний каталог самого агента не изменяется.

## Найти и установить агента

Обновление Registry — явное сетевое действие. Выполните его один раз, затем
посмотрите план установки:

```sh
giga agent search opencode --refresh --json
giga agent add opencode --dry-run --json
```

План фиксирует версию, источник, контрольную сумму, локальный идентификатор и
действия с файлами. Если всё верно, подтвердите тот же выбор:

```sh
giga agent add opencode --yes --json
```

Если идентификатор занят, задайте локальное имя:

```sh
giga agent add opencode --as team-opencode --dry-run --json
giga agent add opencode --as team-opencode --yes --json
```

Не используйте `--allow-unverified`, пока не проверили источник и не приняли
риск артефакта без подтверждённой контрольной суммы.

## Посмотреть состояние и повторить проверку

```sh
giga agent list --json
giga agent inspect opencode --json
giga agent probe opencode --json
```

`inspect` читает сохранённый результат. `probe` запускает короткую проверку в
изолированном окружении: агент инициализируется, но сессия не создаётся и
запрос к модели не отправляется.

В разделе `provider_bridge` важны четыре состояния:

| Состояние | Что означает | Что делать |
|---|---|---|
| `ready` | Агент умеет использовать подтверждённый провайдер модели и маршрут шлюза | Можно выбирать `--with` и `--model` |
| `native_only` | Агент работает, но не умеет безопасно сменить провайдера модели | Запускайте без шлюза |
| `unknown_until_reprobe` | Запись создана старой версией GigaLoom | Выполните `giga agent probe <id> --json` |
| `blocked` | Агент объявил возможность, но текущая проверка не прошла | Исправьте причину и повторите `probe`; не обходите отказ |

Поддержка ACP сама по себе не означает поддержку произвольного OpenAI-адреса.
Например, агент без настраиваемого провайдера модели остаётся `native_only`.
Это не ошибка установки: его нативный запуск продолжает работать.

## Что происходит при установке

GigaLoom:

1. выбирает дистрибутив для текущей системы;
2. показывает ограниченный по времени план;
3. после подтверждения загружает точный артефакт;
4. сверяет контрольную сумму, если она опубликована;
5. распаковывает артефакт в управляемый каталог;
6. запускает проверку без доступа к внешней сети;
7. активирует новую ревизию только после успешной проверки.

На macOS для сетевой изоляции используется системный `sandbox-exec`, на Linux
— Bubblewrap (`bwrap`). Windows и Linux без Bubblewrap пока не поддерживают
управляемую установку из Registry. На таких системах установите CLI агента
самостоятельно и зарегистрируйте локальный манифест.

Если первая загрузка списка агентов отвечает `503 Agent inventory unavailable`,
выполните явное обновление:

```sh
giga agent search "" --refresh --json
```

CLI и браузерный интерфейс должны использовать один `GIGALOOM_DATA_DIR`.

## Обновить или удалить агента

```sh
giga agent outdated --refresh --json
giga agent update opencode --yes --json
giga agent inspect opencode --json
```

Обновление ставится рядом с предыдущей ревизией и не активируется, если новая
проверка не прошла. Для возврата к сохранённой ревизии используйте:

```sh
giga agent rollback opencode --yes --json
```

Перед удалением посмотрите точный план:

```sh
giga agent remove opencode --dry-run --json
giga agent remove opencode --yes --json
```

Удаление управляемой установки не удаляет нативный CLI, его домашний каталог и
учётные данные провайдера модели.

## Зарегистрировать локальный манифест

Локальный манифест подходит для уже установленной программы. GigaLoom сохраняет
ссылку и контрольный хэш файла, но не копирует программу и не выдаёт ей
дополнительные права:

```sh
giga agent add --manifest ./my-agent.toml --dry-run --json
giga agent add --manifest ./my-agent.toml --json
giga agent inspect my-agent --json
giga agent probe my-agent --json
```

Если манифест изменился или исчез, профиль считается устаревшим до явной
замены.

## Воспроизвести установки на другой машине

```sh
giga agent lock --output agent-lock.json --json
giga agent sync --lock agent-lock.json --yes --json
```

Lock-файл содержит версии и данные проверки целостности, но не содержит
учётных данных. Дополнительные причины отказа и безопасные действия перечислены
в [таблице диагностики](troubleshooting.md).
