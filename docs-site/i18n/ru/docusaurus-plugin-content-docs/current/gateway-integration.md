# Интеграция со шлюзом

{/* Release-version snippets in this file are generated by scripts/release.py. */}

Шлюз (gateway) `gpt2giga` принимает запросы в форматах популярных клиентов и
отправляет их в GigaChat. Базовый пакет GigaLoom от него не зависит; интеграция
нужна только для запуска через GigaChat или для Direct Chat.

```sh
uv tool install --force \
  --with 'gpt2giga>=0.3.0,<0.4.0' \
  'gigaloom[gpt2giga]==0.9.0'
```

GigaLoom использует опубликованный пакет. Checkout исходников `gpt2giga` рядом
с репозиторием не нужен.

## Выбрать модель и маршрут

Короткая форма выбирает шлюз и модель:

```sh
giga --with gpt2giga --model GigaChat-2-Max codex
```

Проверить выбор без запуска агента и запроса к модели:

```sh
giga --with gpt2giga --model GigaChat-2-Max --dry-run --json codex
```

Для закреплённого маршрута можно использовать его идентификатор:

```sh
giga --route codex-gpt2giga-gigachat-2-max codex --help
```

Глобальные параметры GigaLoom должны стоять до имени агента. Поэтому
`giga --model GigaChat-2-Max codex` выбирает маршрут, а
`giga codex --model o3` передаёт `--model o3` самому Codex.

Список моделей приходит из `/models`. GigaLoom не угадывает возможности по
имени модели и не подставляет другую модель, если выбранная недоступна.

## Какие протоколы используются

`gpt2giga` предоставляет несколько публичных API, но конкретный агент может
поддерживать только один из них:

| Агент или клиент | Протокол к шлюзу | Состояние |
|---|---|---|
| Codex | OpenAI Responses | Техническое превью; проверяйте результат `--dry-run` |
| OpenCode и совместимые ACP-агенты | OpenAI Chat Completions | Доступно, когда `inspect` показывает `provider_bridge.status=ready` |
| Claude Code | Anthropic Messages | Требует отдельно подтверждённого маршрута клиента |
| Gemini CLI | Gemini GenerateContent | Пользовательский endpoint может быть недоступен для текущей версии клиента |
| Amp или неизвестный ACP-агент | Нативный провайдер модели | Без подтверждённого способа настройки шлюз не выбирается |

Статус `native_only` означает границу возможностей агента, а не сломанную
установку. Запустите такой агент без `--with` и `--model`.

## ACP-агент через шлюз

После установки из Registry проверьте агента:

```sh
giga agent inspect opencode --json
giga agent probe opencode --json
```

Если состояние `ready`, GigaLoom создаёт временную конфигурацию, запускает
ACP-процесс, применяет подтверждённый адрес провайдера модели и только затем
создаёт сессию:

```sh
giga --with gpt2giga --model GigaChat-2-Max opencode
```

Временная конфигурация удаляется вместе с процессом. GigaLoom не пишет в
`~/.opencode`, `~/.codex`, `~/.qwen`, `~/.claude` или `~/.gemini`.

Если агент сообщает, что умеет менять провайдера модели, но проверка или
повторное чтение настройки завершается ошибкой, GigaLoom останавливает запуск.
Он не переключается на неподтверждённые переменные окружения.

## Управляемый и внешний шлюз

Управляемый профиль запускает установленный `gpt2giga`, ждёт готовности и
повторно использует здоровый процесс. После завершения запуска GigaLoom
останавливает только принадлежащий ему процесс.

Внешний профиль подключается к уже запущенному шлюзу. Его жизненным циклом
управляете вы; GigaLoom только проверяет адрес, авторизацию, список моделей и
совместимость API.

В обоих режимах секреты передаются во время запуска и не попадают в вывод
`inspect`, сохранённые результаты проверки или URL маршрута.

## Если маршрут недоступен

GigaLoom останавливает запуск, если не может подтвердить совместимость. Он не
меняет протокол, шлюз, провайдера модели, модель или агента без вашего выбора.

Проверьте:

1. установлена ли дополнительная интеграция `gpt2giga`;
2. доступны ли учётные данные GigaChat в текущем терминале;
3. вернул ли `/models` выбранную модель;
4. показывает ли `giga agent inspect <id> --json` состояние `ready`;
5. не занят ли порт управляемого шлюза другим процессом.

Сопоставьте `reason_ids` с [таблицей диагностики](troubleshooting.md). Нативный
запуск агента без выбора шлюза остаётся доступен, если проблема относится
только к маршруту.
